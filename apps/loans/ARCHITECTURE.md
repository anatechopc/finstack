# Architecture

Detailed overview of the Loooans Flutter application for developer onboarding.

## Project Overview

Loooans is a Flutter-based loans marketplace app that connects borrowers with lending providers. Generated by [Very Good CLI](https://github.com/VeryGoodOpenSource/very_good_cli). Uses FVM for Flutter version management (currently 3.38.4).

The app supports three build flavors (development, staging, production) with separate Firebase backends per environment.

## State Management: BLoC Pattern

All state management uses `flutter_bloc`. Features follow the event-state pattern:

- **Events** trigger state changes in BLoCs
- **States** are immutable, extend `Equatable` for efficient comparison
- UI rebuilds via `BlocBuilder` (reactive rendering) and `BlocListener` (side effects like navigation, dialogs)
- 9 app-level BLoCs are registered in `lib/app/di/bloc_providers.dart` via `MultiBlocProvider`
- Each BLoC accepts its dependencies (like `AuthenticationService`) via constructor parameters rather than accessing singletons directly

### BLoC List

| BLoC | Purpose |
|------|---------|
| `AuthenticationBloc` | Login, logout, session management |
| `LoansBloc` | Loan CRUD, status updates, requirements |
| `PaymentBloc` | Loan schedule payments |
| `LoanSettlementBloc` | Account settlement and confirmation |
| `AdditionalLoanBloc` | Additional loan amounts |
| `ProductBloc` | Loan product/offer management |
| `UserBloc` | User CRUD, co-maker management |
| `CompanyBloc` | Company/provider management |
| `CapitalBloc` | Capital/cash pool management |
| `RegistrationBloc` | User and provider registration |
| `ReportsBloc` | SOA generation, report data |

## Monorepo with Local Packages

The `../../packages/` directory contains ~22 repository packages split into `core/` (shared) and `loans/` (domain-specific) groups (e.g., `loan_repository`, `user_repository`, `authentication_repository`). Each repository:

- Extends `BaseRepository<T>` from `loooans_helpers`
- Uses service layers: `FirestoreService`, `NetworkService`, `RealtimeDatabaseService`, `StorageService`, `CacheService`
- Models implement `BaseModel<T>` with `toEntity()` conversion
- Has its own `pubspec.yaml` and can be independently versioned

Code generation for models uses `build_runner`. Run `../../packages/build_models.sh` to regenerate models across all packages, or run `fvm flutter pub run build_runner build --delete-conflicting-outputs` within a single package.

## Dependency Injection

Manual DI via `MultiRepositoryProvider` and `MultiBlocProvider`:

- **Repositories** are registered in `lib/app/di/repository_providers.dart` (~17 repositories)
- **BLoCs** are registered in `lib/app/di/bloc_providers.dart` (~9 blocs)
- **Singleton services** manage shared state:
  - `AuthenticationService` — current user, company, device, address
  - `NotificationService` — FCM token management, notification stream
  - `SettingsService` — app and user settings
  - `DeviceService` — device info, instance ID

## Routing

GoRouter configured in `lib/app/routing/router.dart`. Route paths defined in `lib/app/routing/paths.dart`.

**Public paths** (no auth required):
- `/` — Landing/index
- `/login` — Login screen
- `/register` — Registration
- `/register/complete` — Registration completion
- `/404` — Not found

**Authenticated routes** are wrapped in a `ShellRoute` that provides the `HomeScreen` navigation frame with sidebar/bottom navigation.

Navigation uses `GoRouter.of(context).goSafe()` — a custom extension that handles route validation.

## Feature Structure

Features live in `lib/features/`. Each feature module follows this structure:

```
feature_name/
├── bloc/           # BLoC, events, states
├── model/          # Feature-specific models
├── screen/         # UI screens (top-level pages)
└── widget/         # Extracted sub-widgets for screens
```

## Firebase Backend

Three Firebase projects mapped to flavors:

| Flavor | Firebase Project | Config File |
|--------|-----------------|-------------|
| development | `loooans-dev-stg` | `lib/firebase_options_dev.dart` |
| staging | `loooans-dev-stg` | `lib/firebase_options_stg.dart` |
| production | `loooans-prod` | `lib/firebase_options.dart` |

**Services used:** Firestore, Realtime Database, Cloud Storage, Cloud Messaging (FCM), Cloud Functions, Hosting.

### Go Backend (Cloud Functions)

Located at `../../functions/loans/`. Firestore triggers handle:

| Trigger | File | Purpose |
|---------|------|---------|
| `loanChanges` | `triggers/loan_changes.go` | Loan report updates + notification creation on status changes |
| `loanScheduleChanges` | `triggers/loan_schedule_changes.go` | Payment report updates |
| `notificationCreated` | `triggers/notification_created.go` | FCM push delivery when notification docs are created |
| `reviewCreated` | `triggers/review_created.go` | Notification creation when reviews are posted |
| `paymentCreated` | `triggers/payment_created.go` | Notification creation when payments are submitted |

Notification creation is handled server-side (Go triggers), not in the Flutter frontend. The Flutter `NotificationService` only manages FCM tokens and reads/displays notifications.

## Code Style & Linting

- Linting: `very_good_analysis` (see `analysis_options.yaml`)
- Prefer single quotes
- `avoid_print: true` — use `debugPrint` or `Logger` instead
- Generated files (`*.g.dart`, `*.gr.dart`, `*.freezed.dart`) are excluded from analysis
- Testing: `bloc_test` for BLoC tests, `mocktail` for mocking

## Localization

ARB files in `lib/l10n/arb/` (English and Spanish). Access via `context.l10n` after importing `package:loooans/l10n/l10n.dart`.
