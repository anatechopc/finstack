# CLAUDE.md

Instructions for Claude Code when working in the loans Flutter app.

> **Monorepo context**: This app lives at `apps/loans/` inside the **finstack** monorepo. Shared packages are at `../../packages/core/` (generic) and `../../packages/loans/` (domain-specific). See the root `CLAUDE.md` for the full monorepo layout.

## Rules

### Must Always

- Use `fvm flutter` for ALL flutter commands — never bare `flutter`
- Run `fvm flutter analyze` after making changes to verify no errors are introduced
- Read a file before editing it
- Prefer editing existing files over creating new ones
- Prefer single quotes for Dart strings
- Use `debugPrint` or the `Logger` class for logging — never `print`
- Follow existing naming conventions and code style in surrounding code
- Keep BLoC event handlers focused — if a handler exceeds ~100 lines, extract a helper method or service
- When extracting widgets, place them in the feature's `widget/` subdirectory
- When creating shared services, place them in `lib/services/`
- Commit only when explicitly asked

### Must Never

- Modify files under `../../packages/` (shared repository packages) without being asked — these are shared across apps
- Modify `firebase_options*.dart` files — these are generated
- Modify `*.g.dart`, `*.gr.dart`, `*.freezed.dart` files — these are generated by `build_runner`
- Push to remote without being asked
- Add `print` statements (linter enforces `avoid_print`)
- Use `AuthenticationService.instance` directly in BLoCs — use the injected `authService` field instead (Phase 8 refactoring)

### Preferences

- When creating new BLoCs, accept dependencies via constructor parameters (not singletons)
- When splitting large files, create a barrel file that re-exports the new files to avoid breaking existing imports
- For UI widgets over ~300 lines, consider extracting sub-widgets into the feature's `widget/` directory
- For BLoC handlers that do network calls, emit a loading state early so the UI can show progress immediately
- Keep `MEMORY.md` updated when completing significant work

## Commands

```bash
# Run app (three flavors)
fvm flutter run --flavor development --target lib/main_development.dart
fvm flutter run --flavor staging --target lib/main_staging.dart
fvm flutter run --flavor production --target lib/main_production.dart

# Analyze
fvm flutter analyze
fvm flutter analyze lib/path/to/specific/directory/

# Tests
fvm flutter test --coverage --test-randomize-ordering-seed random
fvm flutter test test/path/to/test_file.dart

# Code generation (all packages — run from packages/ directory)
../../packages/build_models.sh

# Code generation (single package)
fvm flutter pub run build_runner build --delete-conflicting-outputs

# Localization
fvm flutter gen-l10n --arb-dir="lib/l10n/arb"

# Package management (run from packages/ directory)
../../packages/get_dependencies.sh       # pub get all packages
../../packages/update_dependencies.sh    # pub upgrade all packages
../../packages/clean_package.sh          # clean all packages

# Version bumping
./scripts/bump_version.sh [dev|staging|production]

# Deploy Firestore indexes
./scripts/deploy-indexes.sh [dev|stg|prod]
```

## Project Context

Loooans is a Flutter loans marketplace app. Generated by Very Good CLI. Flutter 3.38.4 via FVM.

For detailed architecture and onboarding, see [ARCHITECTURE.md](ARCHITECTURE.md).

### Key Directories

| Path | Purpose |
|------|---------|
| `lib/features/` | Feature modules (bloc/, model/, screen/, widget/) |
| `lib/services/` | Singleton services and extracted helpers |
| `lib/widgets/` | Shared UI components (barrel file: `app_widgets.dart`) |
| `lib/app/view/` | App root, theme |
| `lib/app/routing/` | GoRouter config, route paths |
| `lib/app/di/` | Repository and BLoC provider setup |
| `lib/utils/` | Constants, extensions, screen helpers |
| `../../packages/core/` | Core shared packages (helpers, auth, user, company, etc.) |
| `../../packages/loans/` | Loans-domain packages (loan, payment, capital, product, etc.) |

### State Management

BLoC pattern via `flutter_bloc`. 9 app-level BLoCs registered in `lib/app/di/bloc_providers.dart`. Each BLoC accepts `AuthenticationService` as a constructor parameter.

### Firebase

- **development/staging**: project `loooans-dev-stg`
- **production**: project `loooans-prod`
- Services: Firestore, Realtime Database, Cloud Storage, FCM, Cloud Functions, Hosting
- Go backend (Cloud Functions): `../../functions/loans/`

### Linting

- `very_good_analysis` (see `analysis_options.yaml`)
- Testing: `bloc_test` for BLoCs, `mocktail` for mocking

### Localization

ARB files in `lib/l10n/arb/` (English, Spanish). Access via `context.l10n`.
